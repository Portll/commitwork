Per-repo configuration

resolved by monitor/discover.mjs + monitor/registry.mjs
Semgrep Pro
Resolved live: explicit projects[] entries (an expand: children entry contributes its children, not itself) plus every git repo found under roots[], with exclude[] and lifecycle{} applied — the identical resolveRepos() call monitor/sweep.mjs makes, so this cannot drift from what is actually scanned. Area ownership is declared, never inferred: an entry's area, else areas[].members, else areas[].prefixes, else the repo's own name. Report output is areas[].out (falling back to the slug). Change any of it in monitor/projects.json.

Semgrep Pro is licensed for a bounded number of repositories, so the engine is allocated per repo rather than fixed in the manifest. Tick the repositories that should get it; the box is offered only on rows that are their own scan unit, because a seat granted to a group entry, a superseded name or an excluded one is a seat spent on nothing. Repositories outside the allocation run the OSS engine and publish real findings — the narrower engine is recorded as a coverage bound (engine-per-repo), never as a reason to discount a number. Which engine actually ran is not taken from this page: each repo’s semgrep.sarif records it at runs[].tool.driver.name. A save above the cap is refused by the registry, not merely disabled here, so no allocation can outlive the licence that permits it.

Scanning

lanes and binary approvals · written to .claude/store/scan-config.json, journalled
history
A lane can be enabled and still held because its binary is unapproved — the two are shown separately because only one of them is something you turn on here. A held lane is reported by the runner as a noscan void with coverage unknown, never omitted: a sweep that dropped it would render "refused" and "clean" identically. The gate stays off entirely until this store exists.

Bound ports

Ownership is joined from docker's published port mappings (never container names, which anyone starting a container chooses) and the registry's declared targets. A port nothing appears to hold is reported as not seen, never as not bound: this observation is unprivileged, so root-owned sockets are invisible to it and no finding may be dismissed on that basis.

Packages

what is installed on this box · observed via monitor/package-inventory.mjs read-only
loading…
Each manager reports outdated against the catalogue it last fetched, not against the internet — so the catalogue's own age travels with the answer. A manager that could not be asked reads UNKNOWN, never up to date: on this surface “nothing is out of date” is the sentence most worth being sure about. Pinned packages are held back on purpose and are named rather than counted as debt. macOS updates are observation-only — they can force a reboot, so applying one is a human act taken at the machine.

Updates

what each applicable update fixes · produced by monitor/update-vulns.mjs read-only
loading…
Fixed is a measurement, not a changelog: the same matcher runs twice, once against what is installed and once against what the update would install, and the difference is what the update closes. What could not be measured says so — an embedded dependency inside a keg has no observable post-upgrade version, so it is reported as vulnerable now, effect UNKNOWN and never as fixes nothing. macOS rows are matched by CPE against NVD's vendor-declared ranges, which is inference tier: the fixed and remaining sets are reported, no severity is published, and each row keeps the claim it was made under. Rows with no fix recorded anywhere are counted separately — no update can close them.

Annotations (Human Log)

append-only · edited in-file with provenance display-only

Annotations monitor/private/annotations.json

Gate exemptions monitor/private/gate-exemptions.json

Stub allowlist monitor/private/stub-allowlist.json

These are append-only judgment logs applied as-of rollup time (each carries who / at / reason, and an optional expires). Never delete an entry — set expires to retire one. Deliberately not editable from this page: a suppression must be a cited decision in the file, not a web click. Signatures marked ⚙ olive were written by an agent, not signed by a person — an agent citing a human ("authorized by …") is still the agent's own claim, so read those as machine-attributed.
