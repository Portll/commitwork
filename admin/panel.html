Accessibility — WCAG 2.2
—

    

    
StateCriterionLevelNameDetailVerified by hand

    
Each row is one WCAG success criterion. fail — checked statically, violations listed · pass — checked statically, none found · unchecked — NOT decidable from static markup: it needs a browser (rendered size, focus obstruction) or human judgement (is this alt text accurate? is the focus order meaningful?). Unchecked is not a pass and it blocks a conformance claim exactly as a failure does — which is why the headline reads unverified rather than conformant while any remain. Level A before AA: an A failure excludes people outright. signed pass — a named person opened the page and verified it by hand; it is not a scanner pass and is counted separately everywhere, it is bound to the exact page content that was checked, and it lapses the moment that content changes. A signed statement by an agent rather than a person is recorded, shown olive, and clears nothing.

    Human oversight
    —
    
    
    
    
    WhenWhoStanceSubjectBasis
    
    
    A record here states that a person read a determination this fleet published and either corroborates it or disputes it. It changes no severity and hides no row — suppression is the scanner-annotation vocabulary’s job, kept separate on purpose, because a mechanism that both attests and suppresses lets “I reviewed this” quietly delete things. dispute is classified as an alarm: a human saying a published determination is wrong is the most expensive finding here, because it is the one a reader can check. Identity is repo/file/rule, never the line — code moves for reasons unrelated to the finding. Absence is its own state: no oversight and disputed are opposite facts and are never rendered alike. Ledger: .claude/verdicts/oversight.jsonl, the same hash chain the gates write to.

    Slop Bucket
    —
      drafts, not decisions — edit before accepting
    
    
    
    
    Comment blocks longer than the schema's limit. The first pass keeps the sentences that
      carry a counterfactual; the second pass drops claims that cannot stand alone and tightens the rest. The original is
      marked against the hatched column: green kept in full, orange reworded, red deleted. A block a heuristic cannot
      collapse without dropping or reordering — a list, or one with no counterfactual — carries no draft, and you write
      the replacement by hand. Save writes the hatched column at once; Accept writes every ticked row. Either way the
      replacement must pass the schema, the file is re-parsed, and a file that stops parsing is restored.

    —
    
    
    
    
    
    
      
    
        
        BOLA probe running…
        
      
    
      
    
    
    
    
    
    
    Object-level authorization testing (bin/bola-run.mjs), one row per project that declares a bola block in monitor/projects.json. Each run mints the declared actor matrix — anonymous, two users and two admins across two tenants — and, for every object one actor owns, checks whether another actor can read it. A 2xx that discloses an object is the finding; the class follows from who reached whose object. Credentials are named, never stored here: a project can only run once its secrets resolve (bin/secrets.mjs), and until then its run reads BLOCKED, not ready. Runs against the declared local testbed base — never the public origin.

    Second factor
    —
    
    
    loading…
    
    
    Enrolled and on are different answers. A secret can exist on the account without a single code ever having been checked against it — bootstrap and every re-issue leave it exactly there — and in that state enforcement is OFF while the account looks provisioned. It is shown as its own state for the same reason a grey scanner is never green. Confirming needs the password as well as a code (a session cookie alone must not be able to turn enforcement on), and disabling needs a valid code from the current authenticator — if that device is gone, the way back is node bin/panel-breakglass.mjs on the box, not this page.
