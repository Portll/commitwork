# The false-clean taxonomy — every way this system has said "fine" while wrong

A **false clean** is any mechanism by which the absence of an alarm is mistaken for the presence
of health. This repository's whole design is organized against the class, but the catalogue of
*instances* was scattered — CLAUDE.md traps, code comments, handoffs, archived remediations. This
doc consolidates it: one durable, stamped, per-incident record. It exists to serve the control-
evaluation work (ground-truth adjudication, injection harness, metrics): every class below is a
thing an injection harness should be able to plant, and every incident is a natural adjudication
candidate. Both halves now exist: the natural incidents below carry retrospective adjudication
records in the ledger (`bin/verdict-journal.mjs --metrics`, 2026-08-11), and
`bin/canary-harness.mjs` plants known-bad states against the live gates and scores the
verdicts — truth by construction, recorded with `canary:` ids in the same ledger.

What it plants, read off `SCENARIOS` on 2026-08-25 rather than from this paragraph's memory of it:
**C1** (T-VANISH), **C3** (T-REG, and T-UNSEAMED since), **C11** twice (T-GARBAGE, R-CORRUPT), plus A1/A2 and the four
attribution worlds, which declare **P1/P5/P6/P9 — not C9**. Two more (T-CLEAN, R-CLEAN) are
`expect: 'quiet'` negative controls and declare no class. C9 is planted by nothing: the attribution
scenarios that once carried it were reclassified into family P when the registry grew to ten
families. The claim entered on a commit (2026-08-11); the reclass landed on a commit (2026-08-13)
and this sentence kept asserting C9 coverage from then until it was read. **Fourteen of the
seventeen classes here have never been planted at all** — argued closures, not scored ones, and
that is the honest state of the harness rather than a gap to be papered over.

Living document: new incidents get a row, not a rewrite. Citations point at the tree, which
carries the full account. The issue store has since moved to `monitor/private/issues.json` in the
private sidecar; rows that cite `monitor/issues.json` measured it at its earlier path.

**Two catalogues, one set of classes.** `monitor/failure-taxonomy.json` (version 17, 207 classes in
11 families) is the machine-readable registry; family I there holds C1 to C37, and this file
records incidents for C1 to C17 under the same ids. It
holds what this file does not — `closure`/`gain` scores, `scoreBasis`, STPA loop and UCA bindings,
and the ten other families a false clean crosses into. This file holds what it does not: the
incidents. **The C-ids, names and mechanisms MUST agree between them, and a disagreement is itself
a C10.** Reconciled 2026-08-25: all seventeen agree, byte-for-byte on names, wording-only on
mechanisms. Validate the registry with `node bin/taxonomy-render.mjs --check`; when adding a class
here, add it there in the same session — C13–C17 were added here on 2026-08-22 and imported there
on 2026-08-23, and for those two days each catalogue was complete and the pair was not.

## Classes

| # | Class | One-line mechanism |
|---|---|---|
| C1 | Absence rendered as success | "not scanned / no data / no file" displays as clean or fresh |
| C2 | Exit code with no subscriber | a check runs, fails, and nothing consumes the failure |
| C3 | Wrong population measured | the number is real but describes a different tree/scope/time |
| C4 | Unstable identity | findings keyed on something that moves (line numbers), so movement reads as change |
| C5 | Tooling self-deception | the measuring instrument lies (search suppresses matches, probe reads wrong field) |
| C6 | Evidence evaporation | the decision was right and printed — and durably recorded nowhere |
| C7 | Suppression without record | noise control that also destroys the record of what was withheld |
| C8 | Oversight racing itself | concurrent gates clobber shared state; the safety layer breaks the safety layer |
| C9 | Attribution absence | an alarm that cannot say WHOSE change it is gets dismissed or mis-baselined |
| C10 | Claim drift | documentation asserts a property the system no longer (or never) had |
| C11 | Unparseable read as empty | a corrupt artifact returns the same shape as a clean one (catch→[]/{}); absence of data indistinguishable from absence of findings |
| C12 | Unconserved pipeline | no invariant binds adjacent stages, so truncation between stages classifies as remediation instead of failure |
| C13 | Empty catalogue read as clean | the scanner ran, enumerated ZERO subjects, and reported the resulting zero as a finding count — "nothing vulnerable" and "nothing looked at" become the same number |
| C14 | The scan mutates its subject | a lane writes to the tree it is scanning, so every lane after it examines a different tree than the batch anchored — the slice records one sliceId over two states |
| C15 | Banner mistaken for output | a tool prints its startup preamble, fails, and exits; the preamble is valid, parseable output, so a reader that checks "did it produce anything" says yes |
| C16 | Unidentifiable build | the tool cannot state which build produced a result, so its zero cannot be tied to a rule set or a database and is unfalsifiable in principle |
| C17 | Update that silently downgrades | the refresh path rebuilds against whatever toolchain is present; coverage regresses while every reported field stays identical |
