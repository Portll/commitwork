Classes of security defect, arranged so that every finding has exactly one home, every entry names
something you can hold a diff against, and every entry declares whether this fleet can prove it,
merely suggest it, or cannot see it at all.

It extends the OWASP Top 10 by **completing** it (the leaves OWASP names only in passing get IDs)
and by **de-nesting** it (OWASP's ten categories became a crosswalk, not ten of the list).

**110 classes at this revision.** The name is the standard's, not a cap. It stood at 100 until
Domains 15 and 16 were added on the ruling that any repository may be the scope; merging ten real
classes back out to hold a round number would be the same defect this document exists to prevent.
Whether the name follows the count is Open decision 5.

## What this is not

commitwork already holds three taxonomies, and they are all about the *observer*:

- [monitor/FAILURE-TAXONOMY.md](../monitor/FAILURE-TAXONOMY.md) (+ [v2](../monitor/FAILURE-TAXONOMY-v2.md), [v3](../monitor/FAILURE-TAXONOMY-v3.md)) — by which proposition the oversight system got the answer wrong.
- [monitor/FALSE-CLEAN-TAXONOMY.md](../monitor/FALSE-CLEAN-TAXONOMY.md) — every way this system has said "fine" while wrong.

Those classify **how reporting fails**. This classifies **what reporting is looking for**. The two
are orthogonal and they meet in exactly one place: the Evidence column below. A class here can be
missed (a failure-taxonomy event) or fabricated (a false-clean mirror), and the Evidence class is
what tells you which of those two is even possible for a given row.

## Four rules the list obeys

**1. A defect, not an attack, and not an outcome.** "Session hijacking" and "privilege escalation"
are things that happen to you; you cannot open a file and fix one. The defects are a token without
`HttpOnly`, and an endpoint that checks authentication but not entitlement. Every entry is phrased
as a property of the system, present tense, so that it can be true or false of a given commit.

**2. One home per class.** Where a class and an instance of that class both appeared, the instance
became a clause. Race conditions in financial transactions are race conditions. Price manipulation
is an unenforced invariant. A taxonomy whose members overlap cannot produce a total.

**3. Level discipline.** The OWASP Top 10 are *roll-ups* — A01 Broken Access Control contains eight
entries below. Listing both the parent and its children as peers double-counts every access-control
finding. OWASP therefore appears as a column, not as rows 1–10, and the crosswalk at the end lets
anyone reading by OWASP find every leaf.

**4. Scope is not a filter.** commitwork runs against whatever repository it is pointed at. No class
is ever dropped because "no repository in scope has one" — the next sweep may add one, and a
taxonomy that shrank to fit today's fleet would publish a confident result for a codebase whose
entire defect surface it had quietly omitted. Completeness is a property of the list; coverage is a
property of the lanes; only the Evidence column is allowed to vary. Domains 15 and 16 exist because
of this rule, and Domain 14 is retained by it.

## The columns

**Kind** — `Flaw`: something present and wrong (fixable at a file:line). `Gap`: something absent
(fixable only by adding a control; there is no line to point at). `Process`: a failure of the
practice around the code, not of the code.

**Evidence** — what this fleet can establish. Read from
[`manifests/security-baseline.json`](../manifests/security-baseline.json) (82 checks; 51 at the tally) and
[`manifests/runtime.json`](../manifests/runtime.json) (7), not from any prose description of the
lanes:

| Class | Meaning | Rendering rule |
|---|---|---|
| **Provable** | A check **in group `all`** produces evidence a reader can independently re-derive — a file:line, a response header, a resolved version. | A zero is a real zero **only if the check ran and exited clean**. Exit code is the second witness. |
| **Provable (uninstalled)** | The check **is** in group `all`, but its binary is absent, so it reports `skip:tool` naming what to install. | The capability is one install away; the published number does not contain it. Must not be read as coverage. |
| **Indicative** | Automation can raise a candidate but cannot settle it; reachability, exploitability or intent remain open. | Belongs in `undetermined`, outside crit/high/med/low, with the original claim preserved. Publishing these as findings is the unsupported finding defect that produced 1,311 false CRITICALs on 2026-08-22. |
| **Unobservable** | No check in any bundled manifest examines it. | **Not examined.** Absence of evidence is its own state. |

Unscanned classes are reported as unscanned. A pass or finding requires a completed check.

### Why `all` versus `deep` is a load-bearing distinction

`monitor/sweep.mjs` defaults with `const group = pos[0] || 'all'`. `monitor/install-agents.mjs`
schedules `sweep.mjs all <slug>` nightly, one area every 15 minutes from 02:30, and
`sweep.mjs deep <slug>` weekly. **The nightly sweep runs group `all`; only the weekly deep sweep
reaches `deep`.**

On 2026-08-24 that group held 39 of the 51 declared checks; twelve capabilities were declared,
installed and invisible to the published number. On the operator's ruling — *allow all tools to be
invoked in a scheduled sweep* — **ten were promoted into `all`, taking it to 49 of 51.** Each was
already gated by `appliesIfSourceExt` and/or `requires.tools`, so a promoted lane costs nothing on a
repository whose language it does not match, and reports `skip:tool` (naming what to install)
rather than a false clean where the binary is absent.

Two duplicates of `sast` remain outside, and neither is a scheduling oversight:

| Still outside `all` | Why it cannot simply be promoted |
|---|---|
| `sast-opengrep` | It declares **the same report file as `sast`** (`semgrep.sarif`). Running both in one sweep does not merely double-count — whichever finishes last erases the other's findings. It needs its own report file before it can join any group `sast` is in. |
| `sast-auto` | A measurement lane: the same three rule packs as `sast` without `--pro-intrafile`, existing to quantify what the Pro engine buys. Its findings duplicate `sast`'s by construction, so promoting it inflates the SAST total with a second copy of the same scan. |

**The guard that should have caught this did not.** `bin/test/manifest-report-ownership.test.mjs`
allowlists the `sast`/`sast-opengrep` shared filename with the justification *"Empty groups[] means
both never run in one sweep"* — but that premise lived in a comment and was never asserted, so a
one-word promotion would have passed the suite while arming the erasure. The allowlist entry now
carries `requiresDisjointGroups: true` and the test proves the writers share no group. Verified by
counterfactual: adding `sast-opengrep` to `all` fails the test with the erasure named.

# Domain 1 — Identity, authentication and session (1–10)

**1. Missing authentication on a protected surface** — a route, admin interface, management port or
internal API is reachable with no credential at all, usually because protection is applied by
convention rather than by default-deny.
`Gap` · A07 · CWE-306 · **Indicative** — nuclei, dast-authz-bola probe a live target for known
paths; nothing enumerates first-party routes and asks which are unguarded.

**2. Weak credential policy and credential-stuffing tolerance** — no lockout, no throttling, no
rejection of known-breached passwords, so an attacker's only cost is bandwidth.
`Gap` · A07 · CWE-307, CWE-521 · **Unobservable**

**3. Weak password storage** — passwords under a fast or unsalted hash, or with a work factor never
raised since the day it was chosen.
`Flaw` · A02 · CWE-916 · **Provable** — Semgrep, CodeQL, gosec

**4. Multi-factor authentication absent or bypassable** — MFA not offered, not enforced by default,
or skippable through the enrolment, step-up or recovery path.
`Gap` · A07 · CWE-308 · **Provable** for platform 2FA (Prowler, GitHub org) · **Unobservable** for
first-party application flows

**5. Account recovery flow defects** — reset tokens that do not expire, survive their own use, are
guessable, or whose delivery link takes its host from a request header.
`Flaw` · A07 · CWE-640 · **Unobservable**

**6. Account and resource enumeration** — a response body, status code or timing differential
confirms whether an identifier exists.
`Flaw` · A01 · CWE-204, CWE-208 · **Indicative** — api-fuzz

**7. Insecure session token handling and fixation** — tokens without `Secure`/`HttpOnly`/`SameSite`,
carried in URLs or logs, or not reissued on authentication and privilege change.
`Flaw` · A07 · CWE-614, CWE-1004, CWE-384 · **Provable** — tls-headers, Semgrep

**8. Session lifetime and revocation failures** — absolute and idle lifetimes unbounded, and
sign-out, password change or role removal does not invalidate server-side state or refresh tokens.
`Flaw` · A07 · CWE-613 · **Unobservable**

**9. Federated identity flow defects** — OAuth 2.0/OIDC/SAML with an unvalidated `redirect_uri`,
missing `state` or PKCE, implicit-flow token leakage, an unverified issuer, or XML signature
wrapping.
`Flaw` · A07 · CWE-347, CWE-601 · **Indicative** — Semgrep

**10. Token validation defects** — a JWT or API token accepted with `alg: none`, an unverified
signature, an attacker-supplied `kid`/`jku`, or unchecked `aud`/`iss`/`exp`.
`Flaw` · A07 · CWE-347 · **Provable** — Semgrep, CodeQL

# Domain 2 — Authorization and trust boundaries (11–18)

**11. Missing function-level authorization** — a privileged operation checks that the caller is
authenticated but not that they are entitled. (Vertical escalation is the outcome; this is the
defect.)
`Gap` · A01 · CWE-862 · **Indicative** — dast-authz-bola, authz-test

**12. Broken object-level authorization (IDOR)** — the identifier in the request selects the record
and nothing checks that the caller owns it. (Horizontal escalation is the outcome.)
`Flaw` · A01 · CWE-639 · **Provable** against a live target with a BOLA manifest (dast-authz-bola,
`manifests/bola/`) · **Unobservable** without one

**13. Broken object-property-level authorization** — the object is the caller's, but individual
fields they may not read or write are returned or accepted anyway.
`Flaw` · A01 · CWE-863 · **Indicative** — api-fuzz against the declared OpenAPI schema

**14. Mass assignment** — request bodies bind wholesale to model attributes, letting a caller set
fields the form never showed (`role`, `isAdmin`, `balance`).
`Flaw` · A01 · CWE-915 · **Provable** — Semgrep

**15. Predictable resource identifiers** — identifiers sequential, timestamp-derived or otherwise
guessable, converting one leaked reference into full enumeration. Independent of 12: a v4 UUID with
broken authorization is still broken, and a sequential id with correct authorization is fine.
`Flaw` · A01 · CWE-340 · **Indicative** — api-fuzz

**16. Cross-tenant isolation failure** — a shared data path (cache key, search index, export job,
background query, report) omits the tenant discriminator that the request path applies.
`Flaw` · A01 · CWE-863 · **Indicative** — authz-test, dast-authz-bola

**17. Implicit trust of internal traffic** — east-west calls between services carry no
authentication, so perimeter entry converts directly into lateral movement.
`Gap` · A04 · CWE-306 · **Unobservable**

**18. Authorization absent on out-of-band paths** — queues, scheduled jobs, exports, webhooks and
callbacks perform privileged work without re-establishing who asked for it.
`Gap` · A01 · CWE-862 · **Unobservable**

# Domain 3 — Injection and interpreter boundaries (19–27)

**19. SQL and ORM injection** — data reaches a relational query as syntax rather than as a bound
parameter, including through raw ORM fragments and unsafe operator maps.
`Flaw` · A03 · CWE-89 · **Provable** — Semgrep, gosec, and CodeQL for Java/Ruby/Python/JS-TS/C++/Swift
(five packs in `all`, Swift in the weekly `deep` sweep) · **Provable (uninstalled)** — Joern, Bearer

**20. Injection into non-SQL query languages** — the same defect against document stores, LDAP
directories, XPath/XQuery documents, and GraphQL filter arguments.
`Flaw` · A03 · CWE-943, CWE-90, CWE-643 · **Provable** — CodeQL, Semgrep

**21. OS command and argument injection** — user data reaches a shell, or reaches an argument vector
where a leading `-` changes what the program does.
`Flaw` · A03 · CWE-78, CWE-88 · **Provable** — CodeQL, Semgrep, gosec, shellcheck

**22. Code injection and unsafe dynamic evaluation** — untrusted data is compiled or evaluated
(`eval`, `Function`, `exec`, dynamic `require`/`import`).
`Flaw` · A03 · CWE-94, CWE-95 · **Provable** — CodeQL, Semgrep

**23. Deserialization of untrusted data** — a serialised object graph from an untrusted source is
reconstructed, invoking constructors and setters the attacker chose.
`Flaw` · A08 · CWE-502 · **Provable** — CodeQL, Semgrep, jackson-caseinsensitive-guard

**24. Server-side template injection** — user data is concatenated into template *source* rather
than passed as a template variable.
`Flaw` · A03 · CWE-1336 · **Provable** — Semgrep

**25. Expression-language and lookup injection** — a string interpolated by an EL, logging or
configuration layer (SpEL, OGNL, JNDI, log4j-style `${}`) carries attacker content.
`Flaw` · A03 · CWE-917 · **Provable** — CodeQL, Semgrep

**26. XML external entity processing and entity expansion** — a parser resolves external entities or
expands recursive ones, yielding file read, SSRF or memory exhaustion.
`Flaw` · A05 · CWE-611, CWE-776 · **Provable** — CodeQL, Semgrep

**27. Prototype pollution and object-key injection** — a merge, clone or dynamic assignment lets a
request set `__proto__`/`constructor`, changing behaviour for objects it never touched.
`Flaw` · A03 · CWE-1321 · **Provable** — Semgrep, CodeQL

# Domain 4 — File, path and archive handling (28–31)

**28. Path traversal and local file inclusion** — a path derived from input escapes its intended
root, or reaches an include/render sink so the file is executed rather than read.
`Flaw` · A01 · CWE-22, CWE-98 · **Provable** — CodeQL, Semgrep, gosec

**29. Remote resource inclusion and unsafe dynamic loading** — code, templates, configuration or
plugins fetched at runtime from a location an attacker can influence, with no integrity check.
`Flaw` · A08 · CWE-829 · **Provable** — Semgrep

**30. Unrestricted file upload** — uploads accepted without validating type, size or destination,
and served from a path where the server will execute them.
`Flaw` · A04 · CWE-434 · **Provable** — Semgrep

**31. Archive extraction traversal and decompression bombs** — archive member names trusted as paths
(Zip Slip), and expansion unbounded in size, depth or member count.
`Flaw` · A03 · CWE-22, CWE-409 · **Provable** — Semgrep, CodeQL

# Domain 5 — Request forgery, protocol and edge (32–38)

**32. Server-side request forgery** — the server fetches a URL the caller controls. Allowlists
defeated by redirects, alternate encodings, or DNS rebinding (the address changes between the check
and the connect) are this class, not separate ones.
`Flaw` · A10 · CWE-918, CWE-350 · **Provable** — Semgrep, CodeQL Java/Ruby/Python/JS-TS ·
**Provable (uninstalled)** — Joern

**33. Instance-metadata and link-local exposure** — an SSRF, proxy or misconfigured egress can reach
`169.254.169.254` or its equivalent, trading one request for cloud credentials.
`Flaw` · A05 · CWE-918, CWE-668 · **Indicative** — nuclei

**34. HTTP request smuggling and desync** — front-end and back-end disagree about where one request
ends, so a prefix can be prepended to somebody else's. A parser-disagreement defect, not an
interpreter-boundary one.
`Flaw` · A05 · CWE-444 · **Indicative** — nuclei

**35. Cache poisoning and cache deception** — a shared cache is made to store the wrong body under a
key, or to store a private body under a public one. Both directions of the same defect: the cache
key does not capture everything that varies the response.
`Flaw` · A05 · CWE-524, CWE-444 · **Indicative** — nuclei

**36. CRLF injection and HTTP response splitting** — control characters in a header value forge a
header or create a second response downstream.
`Flaw` · A03 · CWE-93, CWE-113 · **Provable** — Semgrep, CodeQL

**37. Cross-site request forgery** — a state-changing request authenticates on an ambient credential
alone: no token, no `SameSite`, no origin check.
`Gap` · A01 · CWE-352 · **Provable** — Semgrep, tls-headers

**38. Open redirect and unvalidated forward** — a redirect target comes from input, lending the
site's reputation to a phishing destination and leaking tokens across the hop.
`Flaw` · A01 · CWE-601 · **Provable** — CodeQL, Semgrep

# Domain 6 — Browser and client trust (39–44)

> These are grouped by *where the fix goes*, not by mechanism. All four injection entries below map
> to OWASP A03; they sit here because the sink taxonomy (HTML body, attribute, JS, URL, CSS) and the
> controls (contextual encoding, CSP, Trusted Types) are browser concerns, and pooling them with
> parameterised-query defects hides that the remediation is a different discipline.

**39. Stored cross-site scripting** — attacker-controlled script is persisted and later rendered
into another user's page.
`Flaw` · A03 · CWE-79 · **Provable** — Semgrep, CodeQL Java/Ruby/Python/JS-TS ·
**Provable (uninstalled)** — Joern

**40. Reflected cross-site scripting** — request content is echoed into the response without
contextual encoding.
`Flaw` · A03 · CWE-79 · **Provable** — CodeQL, Semgrep, nuclei

**41. DOM-based cross-site scripting** — client-side code moves data from a controllable source to a
dangerous sink without the payload ever leaving the browser.
`Flaw` · A03 · CWE-79 · **Provable** — Semgrep and `sast-codeql` (JS/TS), which carries the
source-to-sink proof and entered `all` on 2026-08-24

**42. Markup injection without script execution** — unescaped HTML defaces layout, spoofs a login
form, or plants hidden inputs that harvest the browser's autofill.
`Flaw` · A03 · CWE-79 · **Provable** — Semgrep

**43. Missing framing and browser-policy controls** — no CSP, or a CSP permitting `unsafe-inline`;

`Gap` · A05 · CWE-1021, CWE-693 · **Provable** — tls-headers, nuclei

**44. Cross-origin and cross-context messaging misconfiguration** —
`Access-Control-Allow-Origin` reflected or wildcarded alongside credentials, `null` origin accepted,

`Flaw` · A05 · CWE-942, CWE-346 · **Provable** — tls-headers, Semgrep

# Domain 7 — Cryptography and secrets (45–53)

**45. Broken, weak or expiry-blind cryptographic primitives** — MD5, SHA-1, DES, RC4, ECB,
undersized keys; and long-lived secrets whose required confidentiality window outlasts the
primitive, including harvest-now-decrypt-later exposure of data that must stay secret beyond the
classical RSA/ECC horizon.
`Flaw` · A02 · CWE-327, CWE-326 · **Provable** for the primitive · **Unobservable** for the exposure
window (no lane knows how long a given secret must survive)

**46. Insufficient entropy** — tokens, keys, nonces, salts or identifiers drawn from a
non-cryptographic PRNG or a low-entropy seed.
`Flaw` · A02 · CWE-338, CWE-330 · **Provable** — Semgrep, CodeQL, gosec

**47. Insecure key management** — keys stored beside the data they protect, shared across
environments, never rotated, with no separation between who holds them and who uses them.
`Gap` · A02 · CWE-320, CWE-321 · **Unobservable**

**48. Secrets embedded in code, configuration and images** — API keys, database passwords and
private keys committed to the tree, baked into a container layer, or shipped in a client bundle.

# What changed from the draft, and why

## Structural

1. **OWASP demoted from rows to a column.** The draft's items 1–10 contained items 11–100. A01 is
   not a peer of IDOR; it is IDOR's parent. Ten slots were recovered and spent on leaves that had no
   number at all.
2. **Every entry restated as a defect.** "Session Hijacking", "Vertical Privilege Escalation" and
   "Horizontal Privilege Escalation" name outcomes — you cannot fix an outcome. They became
   *insecure session token handling* (7), *missing function-level authorization* (11) and *broken
   object-level authorization* (12). This is the single change that most improves coherence: every
   row can now be true or false of a specific commit.
3. **One home per class.** #18/#47 (TOCTOU / financial races), #11/#46 (IDOR / IDOR-via-UUID),
   #40/#42 (business logic / price manipulation), #57/#58 (TLS / HSTS), #78/#79 (typosquatting /
   dependency confusion), #90/#97 (training-data poisoning / AI supply chain), #93/#94 (model
   inversion / model theft) each collapsed to one entry with the instance as a clause.
4. **Kind axis added.** A `Gap` has no file:line and cannot be found by looking harder at the code;
   a `Process` failure is not in the code at all. Conflating the three is how "we scanned it and
   found nothing" gets written about a control that was never built.
5. **Evidence axis added.** This is the column that makes the list commitwork's rather than
   generic. It names, per class, whether the installed lanes can prove it, only indicate it, or not
   see it — and therefore which rows are permanently grey and must never render as either a pass or
   a finding.

## Added — classes the draft had no slot for

- **SQL, NoSQL, OS command, code injection and deserialization** (19–23). The draft named these only
  inside item 3's parenthetical while giving *XPath injection* its own number. The five
  most-exploited injection classes had no ID; XPath had one.
- **CI/CD workflow injection** (71). The defining GitHub Actions defect, and commitwork's own
  subject matter — `zizmor` runs in the fleet and its findings had nowhere to file.
- **Cloud IAM, public data services, container runtime configuration** (77, 78, 80). The draft's
  only cloud entry was serverless over-privilege. Prowler and Trivy config produce findings today
  with no taxonomy home.
- **Federated identity flows** (9). The draft covered JWT and stopped; OAuth/OIDC/SAML is where the
  bypasses actually live.
- **Account recovery flows** (5) and **account enumeration** (6).
- **Secrets in version-control history** (49), distinct from secrets in the tree (48). TruffleHog
  scans history, Gitleaks scans the filesystem; the remediations differ (rotate vs delete).
- **Algorithmic complexity / ReDoS** (60) — among the most common real defects in Node and Python,
  and entirely absent.
- **Prototype pollution** (27).
- **Replay protection and unsigned webhooks** (53).
- **Cross-tenant isolation** (16) and **authorization on out-of-band paths** (18).
- **Cache deception** (folded into 35); **WebSocket and `postMessage` origin checks** (44).
- **Agentic classes**: tool-call confused deputy, memory poisoning, multi-agent trust, cross-tenant
  RAG retrieval (92–95). The draft's AI domain was model-centric; the live 2026 risk is

- **Domain 15, memory safety and native code** (101–106) and **Domain 16, mobile and embedded

## Deliberately excluded — stated, not left as a silent hole

Rule 4 retired the two exclusions that rested on scope. What remains is excluded on *subject*, which
survives an arbitrary repository:

- **Re-identification and linkability of published datasets.** A privacy-analysis discipline
  (LINDDUN), reached by modelling data subjects rather than by examining a codebase. Handled
  separately, not here.
- **Physical, social-engineering and insider classes.** Not properties of software.
- **Licensing and legal obligations.** commitwork tracks them (`cra/`, `deps-reachability`) but they
  are not vulnerability classes.
- **Client-side tamper, root and jailbreak detection.** Deliberately not a class: against an
  adversary holding the binary these are a delay, not a control, and listing them would invite a
  finding for their absence.
- **Accessibility.** `a11y-wcag` is in group `all` and has no home here, deliberately: its subject
  is a person, not an attacker. The consequence is that lane coverage will never reach 100% against
  this taxonomy, and that is correct rather than a defect to close.

# Coverage plan for Domains 15 and 16

What the 2026-08-24 promotion did and did not reach, and what closing the rest would cost.

## Done

`sast-codeql-cpp` into `all` moved **101–105 from unrun to Provable** — the whole of memory safety
except unsafe-FFI. It is gated to C/C++ extensions, so it costs nothing on the rest of the fleet,
and it runs `build-mode=none`, so it never executes repo-authored build logic. `sast-codeql-swift`
(bounded 900 s) put iOS source in front of a scheduled sweep for the first time; it now runs in the
weekly `deep` sweep, contained because autobuild compiles the scanned repository.

## Sanitizers and fuzzers — a containment decision, not an impossibility

An earlier draft of this plan said commitwork *cannot* adopt sanitizers and fuzzers for arbitrary
repositories, because they require building and running the subject's code and the house rule is
untrusted-by-default. **That was too strong, and the repository already contradicts it.**

`bin/boot-harness.sh` runs `docker build` on the scanned project and then boots the resulting image
— it is already executing third-party application code, deliberately, under
`--cap-drop ALL --security-opt no-new-privileges --pids-limit 256 --memory 2g` on a dedicated
network. Its own comment states the position plainly: it *"REFUSES the host: it runs the scanned
project's application code"*.

`bin/depscan-scan.sh` is the stronger template, and its header names this exact threat model:
resolving an untrusted repo's dependencies *"executes that repo's build logic, and the sandbox is
the only thing standing between that and the operator's keychain"*. Its scan phase runs:

    --network none · -v $SRC:/app:ro · -v $VDB:/vdb:ro · --user 1000:1000
    --cap-drop ALL · --security-opt no-new-privileges
    --pids-limit 512 · --memory 6g · --tmpfs /tmp:rw,noexec,nosuid,size=2g
    timeout $TIMEOUT · --rm · --name (so a timeout can reap it)

That is a textbook sandbox, and `--tmpfs …,noexec` plus `--pids-limit` are exactly the two controls
a fuzzer needs, since a fuzzer OOMs and fork-bombs by design.

**The host boundary here is two layers, not one.** Docker Desktop 4.83.0 runs containers inside a
LinuxKit VM (`linux/arm64`, kernel 6.12.76-linuxkit), so a container escape lands in a disposable VM
rather than on the macOS host holding the operator's keychain. For a corpus containing 26
OSV-confirmed malicious packages that difference is the whole argument.

### What actually blocks it

1. ~~**There is no shared sandbox primitive.**~~ **BUILT 2026-08-24** — `bin/lib/sandbox.mjs`
   (pure), `bin/sandbox.mjs` (a CLI that prints flags and never runs docker), 35 tests.
   Seven declared postures today (`analyse`, `fetch`, `lookup`, `boot`, `resolve`, `build-resolve`,
   `instrument`); the four first built differ only where the tension is real:

   | Posture | Egress | Scratch | Runs repo code | For |
   |---|---|---|---|---|
   | `analyse` | none | `noexec` | no | an analyser reading untrusted source |
   | `fetch` | **bridge** | `noexec` | no — source mount *refused* | the warm phase that makes offline scanning possible |
   | `boot` | **bridge** | — | yes | a boot probe; explicitly NOT for hostile code |
   | `instrument` | none | **exec** | yes | sanitizers and fuzzers |

   Every posture gets `--cap-drop ALL --security-opt no-new-privileges`, a required reapable
   `--name`, and bounded `--pids-limit`/`--memory`. The docker socket, `/`, `/etc`, `/proc` and any
   path containing `.ssh`/`.aws`/`.docker`/`Keychains` are refused **regardless of posture** — no
   posture may opt into a host-equivalent mount. Opening egress on a `none` posture is possible and
   returns a warning the caller must print; it is never silent.

   The isolation is **measured, not asserted**: `bin/test/sandbox-effects.test.mjs` runs four
   throwaway containers and checks that `instrument` scratch actually executes a script, that
   `analyse` scratch actually refuses (`Permission denied`), that `analyse` egress is blocked, and
   — as the control that keeps the previous claim honest — that `boot` egress *succeeds*, so
   "blocked" cannot be produced by a container that merely failed to start. It skips loudly when
   docker is absent, because a not-run isolation check must never read as a pass.

   **Migrated.** `depscan-scan.sh`, `boot-harness.sh` and `lockfile-synth.sh` call `bin/sandbox.mjs`,
   and `deps-osv` and `supply-chain-guarddog` run under `--posture lookup`.
2. **Severing the network is not free, and it is measured.** `depscan-scan.sh` records that with
   `--network none`, cdxgen cannot resolve dependencies: *"Measured 2026-08-23: 0 of 29 repos
   scanned, ~7 min of retries each."* A build-and-instrument lane hits that wall harder than a
   resolver does. depscan's answer is the right shape — a network-on warm phase that touches no
   repo code, then a network-off phase that does — and a sanitizer lane needs the same split.
3. **`boot-harness` still reaches the internet.** Its comment concedes it: the app *"cannot reach
   OTHER containers; it can still reach the internet."* Fine for a boot probe, not fine for
   deliberately hostile code, which would simply exfiltrate. Egress denial is the gap to close
   before anything hostile is executed on purpose.
4. **Hardening may break the tool, and this is unmeasured.** AddressSanitizer wants a large virtual
   address-space reservation and commonly needs `SYS_PTRACE` or a relaxed seccomp profile; the
   `--cap-drop ALL --security-opt no-new-privileges` posture above may prevent it from starting at
   all. That is a claim to *test*, not to assume in either direction — and testing it is the first
   concrete task, because if ASan cannot run under the sandbox the whole tier changes shape.

### The tractable order

Extract the shared primitive first (it pays for itself across five existing lanes and closes the
`deps-osv` weakness). Then measure ASan under it on one known-vulnerable C fixture. Only then decide
between own-code-only instrumentation (P0 in the priority stack, where building is legitimate and
egress can stay open) and a hostile-capable tier with egress denied.

## Cheap and available — two brew formulae, no build required

Both are now built: `sast-c-cppcheck` and `sast-c-flawfinder` run in `all`, each with its own
report file. The table records why they were chosen.

| Lane | Cost | Reaches | Why it adds to CodeQL rather than duplicating it |
|---|---|---|---|
| `cppcheck` | `brew install cppcheck`; formula verified available | 101, 102, 104 | Whole-program-ish checking with no compilation database; catches uninitialised reads and buffer indices CodeQL's default query pack does not ship a query for |
| `flawfinder` | `brew install flawfinder`; formula verified available | 101, 105 | Lexical and CWE-tagged; its speciality is exactly the format-string class (105), which is otherwise thinly covered |

Both are language-gated by the same `appliesIfSourceExt` mechanism, both need `requires.tools`, and
both need their own report file — the `sast`/`sast-opengrep` collision above is the cautionary case.

## The one real hole, and it is small

**Entry 109 was Unobservable at the tally and need not have been.** Nothing in the fleet parsed
`AndroidManifest.xml` or `Info.plist`. A first-party Node check in the shape of `bin/vendor-scan.mjs` or
`bin/minify-detect.mjs` — no external tool, no network, no build, deterministic, atomic write —
would carry:

- **109** — `android:exported="true"` with no `android:permission`; `<intent-filter>` on a
  non-launcher component; `<provider>` with `android:grantUriPermissions`; custom URL schemes and
  universal links in `Info.plist`
- **108** — `android:usesCleartextTraffic="true"`, a missing or permissive `networkSecurityConfig`,
  `NSAppTransportSecurity` → `NSAllowsArbitraryLoads` in `Info.plist`
- **107** — `android:allowBackup="true"` (application data extractable over adb)
- plus `android:debuggable="true"`, which belongs to 76

This is the highest coverage-per-hour item in either domain: one file, one test, one manifest entry.
It is built as `mobile-manifest` (`bin/mobile-manifest.mjs`) in group `all`.

## Considered and rejected

- **MobSF / `apkanalyzer`** — both analyse a *built* APK or IPA. `apkanalyzer` is installed on this
  machine, but almost no source repository ships a built artefact, so the lane would report
  not-applicable on nearly the whole fleet while implying mobile coverage.
- **A Rust `unsafe` counter (`cargo-geiger` or first-party)** — rejected on the house rule, not on
  cost. "This crate contains `unsafe`" is true of most non-trivial Rust: descriptive, not a verdict.
  Publishing it as a finding repeats the GuardDog `capability-*` defect that put 602 of 675 rows at
  `med` for "this package can open a socket". Entry 106 stays grey until something can judge the
  boundary rather than count it.
- **`clang-tidy`** — wants a compilation database, which means configuring the build, which is the
  untrusted-execution problem again.
